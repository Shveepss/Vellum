# Руководство по контрибьютингу (CONTRIBUTING)

Спасибо, что решили помочь в развитии **Vellum**! Мы приветствуем любые вклады: от исправления опечаток до реализации новых крупных функций.

## 🚀 Как начать

1. Сделайте **Fork** репозитория.
2. Создайте ветку для своей задачи (`git checkout -b feature/amazing-feature` или `git checkout -b fix/bug-description`).
3. Внесите изменения.
4. Убедитесь, что все тесты проходят:
   - Бэкенд: `go test ./internal/...`
   - Фронтенд: `cd frontend && npm test`
5. Закоммитьте изменения согласно [правилам оформления коммитов](#правила-оформления-коммитов).
6. Отправьте **Pull Request** в ветку `develop`.

## 🛠 Требования к разработке

### Технологический стек
- **Бэкенд:** Go 1.21+ (используется Wails v2)
- **Фронтенд:** React (TypeScript), Vitest для тестов

### Код-стайл
- Для Go: используйте `go fmt` и придерживайтесь стандартов [Effective Go](https://golang.org/doc/effective_go).
- Для TypeScript/React: используйте Prettier и ESLint (настройки в проекте).

## 📝 Правила оформления коммитов

Мы рекомендуем использовать [Conventional Commits](https://www.conventionalcommits.org/):
- `feat:` — новая функциональность
- `fix:` — исправление ошибки
- `docs:` — изменения в документации
- `test:` — добавление или изменение тестов
- `refactor:` — рефакторинг кода без изменения логики

## 🤝 Процесс ревью

Все PR проходят проверку. Мы можем попросить вас внести правки или уточнить детали реализации. Будьте вежливы и конструктивны.
