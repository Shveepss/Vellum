# Vellum File Manager

**Vellum** — это современный, быстрый и легкий двухпанельный файловый менеджер, построенный на связке Go (бэкенд) и React (фронтенд) с использованием фреймворка Wails. Программа сочетает в себе классический удобный интерфейс в стиле "Total Commander" и современные веб-технологии.

![Vellum Logo](build/appicon_414x411.png)

## ✨ Ключевые возможности

*   🗂️ **Вкладки:** Открывайте несколько независимых вкладок в каждой панели — локальные каталоги, SFTP-сессии и архивы не мешают друг другу.
*   🚀 **Высокая производительность:** Умное кэширование списков файлов и оптимизированные алгоритмы копирования позволяют мгновенно работать даже с огромными директориями.
*   🌐 **Встроенный SFTP-клиент:** Полноценная работа с удаленными серверами. Поддержка профилей, SSH-ключей и безопасных соединений.
*   🌓 **Темная и светлая темы:** Интерфейс, который бережет ваше зрение.
*   🔤 **Гибкая настройка:** Возможность менять шрифты и их размеры прямо в настройках приложения.
*   ⏳ **Фоновые операции:** Копирование, перемещение и удаление файлов не блокируют интерфейс. Следите за прогрессом через наглядные индикаторы.
*   📦 **Портативность:** Приложение поставляется в виде одного исполняемого файла и не требует установки.

## 🚀 Как пользоваться

1.  Скачайте со страницы [Releases](https://gitverse.ru/shveepss/Vellum/releases) архив для своей системы: `Vellum_<версия>_amd64.zip` (64-бит) или `Vellum_<версия>_x86.zip` (32-бит), и распакуйте его.
2.  Запустите файл. Программа автоматически создаст папку настроек в вашем домашнем каталоге (`~/.vellum`).
3.  Для работы с серверами нажмите **F9** и создайте профиль подключения.
4.  Программа сама уведомит вас, если выйдет новая версия.

### Проверка целостности

- **Хэш-сумма.** В каждом архиве рядом с exe лежит `SHA256SUMS.txt`. Проверьте его командой `sha256sum -c SHA256SUMS.txt` или сравните с `Get-FileHash Vellum_amd64.exe` в PowerShell. Хэши самих архивов - в `Vellum_<версия>_SHA256SUMS.txt` на странице выпуска.

## 🛠 Сборка из исходников (для разработчиков)

Если вы хотите собрать программу самостоятельно, вам потребуются:
*   **Go** (1.25+ — версия задана в `go.mod`)
*   **Node.js** (20+) & npm — этого требуют vitest 4 и jsdom 30
*   **Wails CLI** той же версии, что и библиотека в `go.mod` (сейчас v2.11.0):
    `go install github.com/wailsapp/wails/v2/cmd/wails@v2.11.0`

### Команды:

```bash
# Режим разработки (с Hot Reload)
wails dev

# Финальная сборка (64-бит Windows)
wails build -platform windows/amd64
```

Выпуск (обе архитектуры, архивы с exe и `SHA256SUMS.txt`):

```powershell
pwsh scripts/release.ps1              # сборка и архивы
pwsh scripts/release.ps1 -SkipBuild   # архивы из уже собранных exe
```

Результат - в `build/bin`: `Vellum_<версия>_amd64.zip`, `Vellum_<версия>_x86.zip` и `Vellum_<версия>_SHA256SUMS.txt`.

> ⚠️ Указывайте `-platform windows/amd64` явно. Без флага `wails build`
> берёт архитектуру по умолчанию из установленного Go-тулчейна — если он
> у вас 32-битный (`go env GOARCH` вернёт `386`), сборка молча получится
> 32-битной и потеряет аппаратное ускорение AES/SSH-шифрования, из-за чего
> копирование по SFTP становится в разы медленнее (см. CHANGELOG 1.9.7).

### Linux

Проще всего - скриптом (в Linux или в WSL; исходники копируются во временную папку Linux,
так что `node_modules` Windows-сборки не затрагиваются):

```bash
scripts/build-linux.sh --install-deps   # первый раз: поставит GTK, WebKitGTK, Go, Node.js, Wails
scripts/build-linux.sh                  # дальше: только сборка
```

Результат - `build/bin/Vellum_<версия>_linux_amd64.tar.gz`, его хэш дописывается в
`Vellum_<версия>_SHA256SUMS.txt` рядом с Windows-архивами.

Вручную (Ubuntu 24.04, Debian 13 и новее; для WebKitGTK 4.0 - без тега):

```bash
sudo apt install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev
wails build -platform linux/amd64 -tags webkit2_41
```

Выпуск целиком собирает CI на GitVerse: тег значимой версии `X.Y.0`, например `1.13.0` (можно и `v1.13.0`; он должен совпадать с версией в `wails.json`)
или ручной запуск задачи Release кладёт в артефакт `vellum-release-<версия>` архивы
Windows amd64 и x86, Linux и общий `Vellum_<версия>_SHA256SUMS.txt` — остаётся загрузить их в релиз.
Теги промежуточных версий (`1.12.5`) выпуск не собирают — их архивы собираются локально
(`scripts/release.ps1`, `scripts/build-linux.sh`) или ручным запуском задачи Release.

CI на GitVerse собирает Linux-версию при каждом пуше (проверка сборки), а архив
`Vellum_<версия>_linux_amd64.tar.gz` с `SHA256SUMS.txt` выкладывает в артефакты
(`vellum-linux-amd64`) только для версий `X.Y.0`.

Что в Linux устроено иначе, чем в Windows:
- диски - это точки монтирования: `/`, отдельный `/home`, флешки в `/media` и `/run/media`, сетевые папки в `/mnt`;
- Delete удаляет в корзину freedesktop.org - общую с GNOME, KDE, Xfce, так что удалённое можно восстановить из корзины файлового менеджера;
- F4 открывает первый найденный графический редактор (GNOME Text Editor, gedit, Kate, KWrite, Mousepad, xed, Pluma, FeatherPad), а без них - `xdg-open`;
- буфер обмена с файлами (Ctrl+C/X/V с файловыми менеджерами) работает через `wl-clipboard` (Wayland) или `xclip` (X11) — установите один из них: `sudo apt install wl-clipboard xclip`;
- файлы перетаскиваются между панелями и в файловые менеджеры;
- системного меню Проводника нет, вместо него — встроенное меню Vellum.
