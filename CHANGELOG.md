## [1.12.14] - 2026-10-14

### ✨ Добавлено

- **Видео и аудио в окне просмотра (Ctrl+Q и F3).** Раньше видео- и аудиофайлы открывались как двоичные — hex-дампом. Теперь видео (`mp4`, `m4v`, `mov`, `webm`, `ogv`, `mkv` и другие) по умолчанию открывается во встроенном проигрывателе, аудио (`mp3`, `wav`, `ogg`, `opus`, `flac`, `m4a`, `aac` и другие) — в аудиоплеере. Перемотка работает: файл читается частями, а не грузится целиком. Переключатель в окне просмотра — «Видео» или «Аудио», «Текст», «Hex» — позволяет посмотреть файл иначе. Встроенный проигрыватель — это движок окна программы, поэтому он воспроизводит форматы, которые понимают браузеры: контейнеры MP4, WebM, Ogg, частично MKV и MOV с кодеками H.264, VP8/VP9, AV1, AAC, Opus, MP3. Если формат ему не по силам, вместо пустого плеера появляется подсказка с кнопкой «Открыть в программе по умолчанию». Эта же кнопка есть на панели окна просмотра у всех видео- и аудиофайлов с диска — файл открывается в системном проигрывателе. В Windows форматы Microsoft (`avi`, `wmv`, `wma`, `asf`) движок окна не воспроизводит вовсе, поэтому они сразу открываются как содержимое файла, а посмотреть их можно в программе по умолчанию. В Linux такие файлы, как и остальные, сначала пробуют воспроизвестись: WebKitGTK играет через GStreamer и с плагинами `gstreamer1.0-libav` может их показать. Файлы внутри архивов и на SFTP по-прежнему показываются текстом или hex-дампом: проигрыватель читает только файлы с диска.

### 🐛 Исправлено

- **Вставка из буфера обмена при совпадении имени спрашивает, что делать.** Раньше Ctrl+V (и Shift+Insert) молча создавали «имя - копия». Теперь:
  - вставка в другую папку, где уже есть файл с таким именем, показывает тот же диалог, что и копирование по F5: заменить, пропустить, переименовать, в том числе «для всех». Все файлы вставляются одной операцией, поэтому «для всех» действует на всю вставку;
  - вставка в ту же папку, откуда скопировано, спрашивает «Создать рядом копию?»: заменить файл самим собой нельзя. «Отмена» ничего не копирует;
  - вырезанное и вставленное на то же место остаётся на месте без вопросов.

## [1.12.13] - 2026-10-13

### ✨ Добавлено

- **Запуск кнопок панели инструментов от имени администратора.** В редакторе кнопки появился флажок «Запускать от имени администратора», по умолчанию он снят. В Windows при нажатии такой кнопки появляется запрос UAC; отказ в нём — не ошибка, ничего не запускается. Работает и вместе с «Запускать скрипт через» — интерпретатор со скриптом запускается с правами администратора. В Linux команда запускается через `pkexec`. Для внутренних команд (`cm_...`) и переключения панелей (`.bar`) флажок недоступен: их выполняет сам Vellum. Настройка сохраняется в `.bar`-файле ключом `runasadminN`.

### 🐛 Исправлено

- **Backspace иногда открывал каталог пользователя (`C:\Users\<пользователь>\...`).** Выход из уже закрытого архива возвращал домашний каталог. Так бывало при двойном Backspace в корне архива, когда второе нажатие приходило раньше, чем панель сменила путь, и в восстановленной сессии, где панель стоит внутри архива. Теперь панель выходит в каталог, где лежит архив, а запоздавший ответ игнорируется, если панель уже ушла.
- **Панель становилась пустой и не оживала до перезапуска.** Ошибка чтения при автообновлении или при возврате на вкладку (например, сетевая папка не ответила после сна компьютера) стирала список без всякого сообщения. Теперь прежний список остаётся на месте, над ним появляется полоса «Не удалось прочитать папку: <причина>» с кнопкой «Повторить», а следующее удачное обновление её убирает. При переходе в недоступную папку тоже показывается причина, а не пустая панель. Вкладка, путь которой внутри архива, открывает архив заново, если он был закрыт: раньше такой путь читался как обычная папка на диске и не открывался.
- **Журнал.** Ошибки чтения каталогов теперь записываются в журнал (`~/.vellum/logs/vellum.log`) — путь, вкладка и причина. Пути внутри архивов больше не ставятся на отслеживание изменений, и предупреждения «Failed to watch path» на каждый переход по архиву пропали.

## [1.12.7] - 2026-10-06

### ✨ Добавлено

- **Кнопки панели инструментов запускают скрипты.** В редакторе кнопки появилось поле «Запускать скрипт через» с выпадающим списком: командная строка (cmd), Windows PowerShell, PowerShell 7, Python, JavaScript (Node.js), Windows Script Host (VBS, JS), Bash; в Linux — sh, Bash, Python 3, Node.js, PowerShell. По умолчанию не выбрано ничего — команда запускается как обычная программа, как раньше. Пункт «Выбрать программу...» позволяет указать любой другой интерпретатор: скрипт передаётся ему первым параметром. В поле «Команда» указывается путь к скрипту, в «Параметрах» — его аргументы с макросами. В Windows скрипт открывается в своём окне консоли, чтобы были видны вывод и запросы. Пути с пробелами и параметры в кавычках передаются в cmd правильно. Выбор сохраняется в `.bar`-файле отдельным ключом `runwithN`, Total Commander его пропускает.

### 🐛 Исправлено

- **Закладки на сетевые папки.** Кнопка добавления спрашивала только имя, а путь всегда брала из текущей папки. Поэтому сетевой путь (`\\mek\Shared`), введённый в это окно, становился именем закладки на совсем другую папку. Теперь у закладки два поля — «Имя» и «Путь» (по умолчанию — текущая папка, можно ввести любую локальную или сетевую). Кавычки и пробелы по краям пути убираются. У существующей закладки можно изменить не только имя, но и путь. Если папка недоступна (сервер выключен, нет прав), появляется сообщение, окно закладок остаётся открытым. Надписи окна переведены.
- **Backspace иногда открывал каталог пользователя (`C:\Users\<пользователь>\...`).** Причин было две:
  - выход наверх из пути вида `C:` (диск без слеша) вёл в `C:.` — для Windows это текущий каталог программы, а не корень диска. Теперь из `C:` панель переходит в `C:\`, а путь `C:` открывает корень диска;
  - панель при переходе (вход в папку, выход наверх, ввод пути) сообщала о нём так, что событие возвращалось в неё же, и каталог открывался второй раз. При быстрых повторных Backspace эти повторы приходили не по порядку и уводили панель назад. Теперь повтора нет, а запоздавший ответ на выход наверх игнорируется, если панель уже ушла в другой каталог.

## [1.12.0] - 2026-09-30

### ✨ Добавлено

- **Автообновление.** «Справка → Проверить обновления» при найденной новой версии открывает окно: «Скачать и установить», «Страница релиза», «Позже».

  - Перед установкой проверяются две контрольные суммы: архива — по `Vellum_<версия>_SHA256SUMS.txt` из того же релиза, программы — по `SHA256SUMS.txt` внутри архива. Если хоть одна не сошлась или в релизе нет нужного файла, ничего не устанавливается и остаётся ссылка на страницу релиза.

  - Работает для релизов, где файлы названы так, как их называет `scripts/release.ps1` или задача release в CI.

### 🔄 Изменено

- **Выпуск собирается в CI.** Тег `v<версия>` (или ручной запуск задачи Release) на GitVerse собирает архивы Windows amd64, Windows x86 и Linux с общим `Vellum_<версия>_SHA256SUMS.txt` и кладёт их в артефакт `vellum-release-<версия>`. Если тег не совпадает с версией в `wails.json`, сборка останавливается. Публикация в релиз по-прежнему ручная.

## [1.11.5] - 2026-09-23

### 🐛 Исправлено

- **Перемещение удаляло пропущенные файлы.** При перемещении каталога файл, для которого в диалоге конфликта выбрано «Пропустить» («Пропустить все»), не копировался, но источник после операции удалялся целиком — вместе с этим файлом, то есть безвозвратно. Пропущенные файлы теперь запоминаются, и источник удаляется в обход них (каталоги, в которых они лежат, тоже остаются).
- **Копирование файла в самого себя обнуляло файл.** Если обе панели (вкладки) смотрят в одну директорию и на конфликт отвечали «Заменить», `Create()` усекал файл, который в этот же момент читался, и на выходе получался пустой файл. Такое копирование теперь отклоняется с понятной ошибкой. Заодно запрещено копирование и перемещение каталога внутрь собственного подкаталога — раньше сбор задач рекурсивно натыкался на только что созданные копии и строил цепочку вложенных папок до предела глубины.
- **Сравнение файлов (diff) падало на файлах длиннее 10 000 строк.** Таблица LCS обрезалась по 10 000 строк, а обратный проход шёл по полным массивам — отличие ближе к концу файла давало панику (index out of range). Плюс таблица на 10 000×10 000 занимала около 800 МБ, а результат собирался за O(n²). Теперь общие начало и конец файлов отрезаются, LCS считается только по изменённой середине и с ограничением по памяти; если и середина слишком велика, она показывается блоком «удалено»/«добавлено».
- **Утечки и потерянные ошибки при копировании.** Горутина фонового чтения оставалась висеть при ошибке записи (удерживая буферы на 4 МБ и продолжая работать с уже закрытым источником — для SFTP это грозило рассинхронизацией протокола в чужой операции); ошибка `Close()` файла назначения игнорировалась, из-за чего недописанный файл считался успешно скопированным (для SFTP и буферизованной записи именно в `Close()` проявляются ошибки отложенных записей); контексты завершённых задач не освобождались, а сами задачи оставались в списке активных после отмены или паники.
- **Подмена ключа хоста SSH (MITM).** Подтверждение неизвестного хоста открывало второе соединение и сохраняло в `known_hosts` тот ключ, который пришёл уже в нём, — то есть проверка отпечатка пользователем ничего не гарантировала. Теперь `ConfirmHostKey` получает подтверждённый отпечаток и сохраняет ключ, только если он совпадает.
- **Падение приложения при неудачной загрузке known_hosts.** Если база не инициализировалась при старте, обратный вызов проверки ключа обращался к `nil` внутри горутины SSH-рукопожатия, где паника не перехватывается. Теперь подключение просто отклоняется с ошибкой.

- Экспериментальная попытка перетащить файл ИЗ Vellum в Проводник/на Рабочий стол (для локальных файлов, один файл за раз) - у Wails нет штатной поддержки такого перетаскивания, поэтому используется низкоуровневый механизм браузера (Chromium), которым построен интерфейс Vellum; надёжность не гарантируется на всех системах. Основной и надёжный способ вынести файлы из Vellum - через буфер обмена (Ctrl+C/Ctrl+X + вставка в Проводнике), см. выше.

### 🔧 Технические детали

- При перемещении, вырезанном в Vellum и вставленном в Проводнике, сам Проводник отвечает за удаление исходника при своей вставке (так работает системный флаг "переместить") - Vellum не пытается отследить, когда/если внешняя вставка произошла.

- После перезапуска первая вкладка каждой панели открывалась в каталоге той вкладки, которая была активна последней перед закрытием, а не в своём собственном сохранённом каталоге — при двух вкладках это выглядело так, будто обе открылись в одном и том же месте. Восстановление первой вкладки теперь берёт путь из её собственной сохранённой раскладки, а не из общего «последнего активного пути».
- Просмотр архивов: открытие архива всегда показывало пустую панель — путь внутри архива (виртуальный, вида `a.zip::папка`) ошибочно прогонялся через проверку "существует ли такой путь на диске", которая закономерно не проходила. Починено для обеих панелей и для всех операций (листинг, подсчёт размера папки, плоский список для поиска).
- При выходе из архива (`..` на его корне) выделение сбрасывалось на первую строку вместо архивного файла, из которого вышли.
